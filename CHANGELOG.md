# Changelog

## 1.2.10-g9n9n-idle-activity-fix

- Stopped treating every ATVV control notification as user activity. In
  particular, the `CAPS` response generated by the 60-second idle health
  refresh was resetting the 15-minute maintenance timer forever.
- User activity is now recorded only for HOGP keys, voice start/release,
  AUDIO_SYNC and real audio frames. CAPS and other automatic control traffic
  continue to update the ATVV liveness timestamp but do not block idle
  maintenance.
- Rebuilt successfully and passed all 6 native tests.
- Hardware verification: after about 900 seconds without user activity the
  device rebooted with `reset_reason=3`; BLE reconnected automatically, UAC
  mounted, the heartbeat stayed at 0-4 ms, and `voice_timeout_count` remained 0.

## 1.2.9-g9n9n-nonblocking-scan-watchdog

- Fixed the actual long-idle failure: `NimBLEScan::start(0, false)` selected
  the blocking overload, where duration `0` means forever. The BLE task stayed
  trapped inside `start()` and never reached its state-machine loop, heartbeat,
  or the previous idle-maintenance code.
- Changed startup scanning to the non-blocking overload
  `start(0, nullptr, false)`. The BLE task now returns from initialization and
  continuously services scanning, HOGP, ATVV, audio, reconnect and watchdogs.
- Added `ble_task_heartbeat_age_ms` to `/api/status` and CLI diagnostics.
- Confirmed after flashing that the heartbeat is approximately 1-3 ms and the
  log contains `Continuous scanning for Xiaomi Bluetooth Remote active`.

## 1.2.8-g9n9n-main-loop-watchdog

- Moved idle maintenance out of the BLE task and into the main Arduino loop, so
  a blocked BLE task cannot prevent its own recovery.
- Added a main-loop BLE heartbeat watchdog. A missing BLE task heartbeat for
  30 seconds triggers an automatic restart, limited to three consecutive
  attempts until successful user activity clears the persisted counter.
- Added the main-loop maintenance call to `loop()`.

## 1.2.7-g9n9n-idle-maintenance-v2

- Replaced the permanent `idle_reset_done` marker with the versioned
  `idle_reset_done_v2` NVS key and explicitly removed the legacy key during
  initialization. A stale 1.2.6 marker could otherwise suppress maintenance
  forever after a reboot or reflash.
- Changed idle maintenance into a bounded periodic policy: the first reboot is
  allowed after 15 minutes without user activity; after that, another reboot is
  allowed only after a 60-minute cooldown. HOGP, ATVV or audio activity clears
  the marker immediately.
- Added `/api/status` and CLI diagnostics:
  `idle_maintenance_done`, `idle_activity_age_ms`, and
  `idle_maintenance_due_ms`.
- Rebuilt successfully and passed all 6 native tests.

## 1.2.6-g9n9n-idle-maintenance

- Fixed a false voice-session timeout caused by reusing the stale `now`
  captured at the beginning of `ble_remote_task()`. The watchdog now reads
  `millis()` immediately before comparing it with the volatile ATVV activity
  timestamp, so valid AUDIO/SYNC traffic always extends the session.
- Made the audio timestamp volatile so the watchdog observes cross-task updates
  without relying on cached values.
- Added a last-resort idle maintenance reboot after 15 minutes without HOGP,
  ATVV or audio activity. It is suppressed while a voice session or UAC stream
  is active.
- Persisted the maintenance marker in NVS to prevent a reboot loop. Any later
  button or ATVV activity clears the marker and re-arms maintenance.
- Rebuilt successfully and passed all 6 native tests.

## 1.2.5-g9n9n-idle-recovery

- Increased the stuck voice-session timeout from 3 to 5 seconds after hardware
  logs showed a false timeout when a valid SYNC arrived near the boundary.
- Made the audio timestamp volatile and based the watchdog on the synchronized
  ATVV activity timestamp, avoiding a stale cross-task read.
- Rebuilt without changing the 1.2.4 idle refresh and recovery behavior.

## 1.2.4-g9n9n-idle-recovery

- Added a 60-second idle ATVV health refresh that re-subscribes AUD/CTL and
  queries CAPS without restarting the device.
- Recover when the GATT callback is missed but the BLE state still claims to be
  connected.
- Recover when only AUD or CTL is missing instead of waiting for CMD to disappear.
- Reduced the stuck voice-session timeout from 10 seconds to 3 seconds; repeated
  timeouts escalate to one BLE reconnect.
- Added `/api/status` diagnostics: `reset_reason`, `ble_link_connected`,
  `atvv_activity_age_ms`, `voice_timeout_count`, `atvv_refresh_count`,
  `atvv_refresh_fail_count`, and `ble_recovery_count`.
- Verified on hardware with speech working, two successful idle refreshes, zero
  refresh failures, zero automatic recoveries, and zero voice timeouts.

## 1.2.3-g9n9n-lcd

- Added ES3C28P ILI9341 status display.
- Added BLE, ATVV, audio frame, UAC, AGC, buffer, and uptime diagnostics.
- Added status telemetry to `/api/status`.
- Added Chinese 4bpp status-font subset generation.
- Preserved the existing G9N9N HID and UAC behavior.
- Reduced LCD SPI transactions from 20-row to 4-row chunks and paused status
  rendering while BLE voice or UAC streaming is active. This prevents the LCD
  refresh from starving the 2 ms isochronous UAC IN endpoint.
- Verified Windows DirectShow capture and a real G9N9N voice session with
  `uac_streaming=true`, continuously increasing UAC transfers, decoded ATVV
  frames, no re-enumeration, and no UAC error.

## 1.2.2-g9n9n

- Added conservative near-field AGC.
- Added keycode help dialog.
- Improved custom key recording UI.
- Fixed voice session restart and UAC recovery.
